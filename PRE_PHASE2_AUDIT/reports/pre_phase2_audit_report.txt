AUDIT ITEM 1: Feature Selection Nesting (Phase 1B)
======================================================================

STATUS: ISSUE FOUND — Non-nested feature selection
SEVERITY: MAJOR LIMITATION

EVIDENCE CHECKED:
  - run_phase1b_ml.py, step2_feature_matrices() (lines 121-405)
  - ml_pipeline_log.txt (lines 19-33)
  - model_selection_report.txt

FINDINGS:
  Feature selection (variance filter → top 1000, then univariate Cox
  p<0.05 → 127 genes) was performed ONCE on the full training set
  (n=738) BEFORE cross-validation. This is confirmed by:
  1. step2_feature_matrices() runs variance filter and univariate Cox
     screening on all 738 training patients (line 322-350).
  2. The resulting 127 genes are stored in selected_genes and used
     to construct X_train (line 362).
  3. step5_6_train_models() receives X_train with 143 features already
     selected — CV folds operate on this pre-selected feature set.
  4. No sklearn Pipeline wrapping feature selection inside CV folds.
  5. No GridSearchCV with nested CV structure.

BIAS DIRECTION:
  Optimistic bias in CV C-index. The 127 genes were selected using
  outcomes from all 738 training patients, then CV evaluates on
  folds that are subsets of those same 738 patients. Each CV test
  fold's genes were pre-selected using information from that fold's
  outcomes. This inflates apparent CV performance.

IMPACT ON INTERPRETATION:
  The reported CV C-index (CoxPH=0.6486) is optimistically biased.
  The validation C-index (0.5944) is UNAFFECTED — the validation set
  was not used for feature selection. The validation C-index is the
  reliable performance estimate. The gap between CV (0.6486) and
  validation (0.5944) C-index is partly explained by this bias.

  This does NOT invalidate the model or the validation results. The
  frozen 127-gene panel and the validation performance are scientifically
  usable. The CV C-index should not be reported as an unbiased
  generalization estimate.

REQUIRED DOCUMENTATION:
  Phase 2 reports must state: "Feature selection was performed on the
  full training set prior to cross-validation (non-nested design).
  CV C-index values are optimistically biased; validation C-index
  is the unbiased performance estimate."

AUDIT ITEM 2: Multiple Testing Correction
======================================================================

STATUS: ISSUE FOUND — No FDR correction applied
SEVERITY: MAJOR LIMITATION

EVIDENCE CHECKED:
  - run_phase1b_ml.py, lines 327-350
  - ml_pipeline_log.txt, line 29: "After univariate Cox screening
    (p<0.05): 127 genes"

FINDINGS:
  Univariate Cox screening used a raw p-value threshold of p<0.05
  on 1000 genes (after variance pre-filter). No Benjamini-Hochberg
  FDR correction, Bonferroni correction, or any multiple testing
  adjustment was applied.

  With 1000 tests at alpha=0.05, the expected number of false
  discoveries under the null is 50. The 127 significant genes
  likely include some false positives. However, the variance
  pre-filter (top 1000 most variable) reduces the effective number
  of independent tests, and the subsequent Cox penalization (penalizer
  =1.0 for the selected model) provides additional regularization.

  The false discovery inflation is partially mitigated by:
  1. Variance pre-filtering (reduces from 60,660 to 1,000 genes)
  2. Cox L2 penalization on the final model (penalizer=1.0)
  3. The model's validation C-index (0.5944) confirms the panel
     has real predictive signal beyond noise

REQUIRED DOCUMENTATION:
  Phase 2 reports must state: "Univariate Cox screening used a raw
  p<0.05 threshold without FDR correction on 1000 pre-filtered genes.
  Some false discoveries may be included in the 127-gene panel.
  The panel's predictive value is confirmed by validation performance."

AUDIT ITEM 11: Survival Outcome Integrity
======================================================================

STATUS: ISSUE FOUND — Invalid survival observations exist
SEVERITY: MAJOR LIMITATION

EVIDENCE CHECKED:
  - TCGA_train.csv (814 rows, before dropna):
    OS_time = 0: 5 patients (3 with event=0, 2 with event=1)
    OS_time = NaN: 76 patients (7 with event=1)
    OS_event values: {0: 491, 1: 323} — all 0/1, no invalid values
  - TCGA_internal_validation.csv (204 rows, before dropna):
    OS_time = 0: 1 patient (event=0)
    OS_time = NaN: 23 patients (1 with event=1)
    OS_event values: {0: 123, 1: 81} — all 0/1, no invalid values
  - Phase 1B pipeline (step2_feature_matrices, line 133):
    dropna(subset=["Overall_Survival_Time", "Survival_Status"])
    → Train: 814→738, Val: 204→181

FINDINGS:
  1. NaN OS_time with event=1 (impossible combination):
     - Train: 7 patients (e.g., TCGA-56-6546, TCGA-63-5128, etc.)
     - Val: 1 patient (TCGA-75-5122)
     These are correctly DROPPED by the pipeline (dropna on
     OS_time). They do NOT enter modeling. This is handled correctly.

  2. OS_time = 0 with event=1 (impossible survival duration):
     - Train: 2 patients (TCGA-05-4395, TCGA-77-A5GB)
     These have OS_time=0.0 and Survival_Status=1 (dead). Zero
     follow-up with a death event is biologically impossible (death
     must occur at some positive time). These are NOT dropped by
     the pipeline (0 is not NaN) and ENTER modeling.
     - Val: 0 such cases

  3. OS_time = 0 with event=0 (censored at time 0):
     - Train: 3 patients, Val: 1 patient
     These represent immediate censoring — technically valid but
     uninformative. They enter modeling but contribute minimally.

IMPACT:
  2 patients with OS_time=0 and event=1 in the training set are
  invalid survival observations. Their presence may slightly
  distort the Cox model fitting (zero-duration events). However,
  with 738 training patients and only 2 invalid cases (0.27%),
  the impact on model coefficients is negligible.

  The Phase 1B pipeline correctly drops NaN-OS_time patients but
  does NOT filter OS_time=0. This is a minor data quality gap.

REQUIRED DOCUMENTATION:
  Phase 2 reports should note: "2 training patients had OS_time=0
  with event=1 (biologically impossible). These were retained in
  modeling due to a pre-processing gap. Impact is negligible (0.27%
  of training set)."

RECOMMENDED ACTION (not blocking):
  Add OS_time > 0 filter to future preprocessing revisions. Do NOT
  retrain — the 2 cases have negligible impact on the frozen model.

DOCUMENTED LIMITATIONS (must state explicitly in all Phase 2 reports):
  1. Non-nested feature selection (Item 1): CV C-index is
     optimistically biased. Validation C-index (0.5944) is the
     unbiased estimate. The frozen 127-gene panel is usable.
  2. No FDR correction (Item 2): Some false discoveries may exist
     in the 127-gene panel. Mitigated by variance pre-filtering and
     Cox L2 penalization.
  3. Sex variable absent (Item 3): Gender data was not available in
     the downloaded TCGA clinical files. Sex is an unmeasured
     confounder. The frozen model does not use Sex.
  4. 2 invalid survival observations (Item 11): TCGA-05-4395 and
     TCGA-77-A5GB have OS_time=0 with event=1. Impact is negligible
     (0.27% of training set).
  5. RNA-seq-vs-microarray platform gap (Item 9): Applies equally
     to all four GEO validation cohorts. Not corrected in Phase 1D.
  6. Model load verification (Item 14): Should be confirmed in the
     original training environment before Phase 2 execution.
